# DN-62 Localisation conventions (2.3, SDP-2.3 §4)

This note is the rulebook for moving GIS Workbench's user-visible text into message catalogues (phases L0–L5). It also tells reviewers what correct code looks like. Requirements: REQ-L10N-01..25 (PRD 0.4 §6.25).

## The API (`app/src/i18n/index.js`)
```js
import { t, tc, N_, tr, gwError, msgOf } from '../i18n/index.js';
import { num, int, pct, date, dateTime, list, bytes, length, area, height, speed, collator, words } from '../i18n/format.js';
```

| Call | Use |
|---|---|
| `t('English source {name}', { name })` | Any message the user sees. The English text is the key. |
| `tc('menu', 'View')` | When one English word needs two translations: a context string, then the source. Use only where needed: verb and noun ("Open", "Export"), menu and button labels that collide. |
| `N_('Label')` | Marks a literal in a data table (command registry, ribbon data, preference rows, option lists) for extraction. The code that shows it calls `tr(value)`. |
| `tr(v)` | Translates a value that came through `N_`, or a `{src, params}` pair. Non-strings pass through. |
| `gwError('Not a {kind} file', { kind }, 'E_CODE')` | Throws an error that keeps its key and params; `e.message` is the English text. Use it for errors whose text includes values (file names, numbers) and is shown to the user. |
| `msgOf(e)` | The message of a caught error in the UI language. Use it wherever `e.message` is shown: toasts, Import Log, dialogs. |

## Message rules
1. **Whole sentences.** Never build a sentence from translated pieces (`t('Opened') + ' ' + n + ' ' + t('files')`). Write `t('Opened {n, plural, one {# file} other {# files}}', { n })`.
2. **Plurals** use ICU plural syntax, not `n > 1 ? 's' : ''` and not "(s)". Always give `one` and `other`; add `=0` when zero reads differently.
3. **Placeholders** have short descriptive names: `{file}`, `{n}`, `{layer}`, `{msg}`. Pass values; never format numbers into the string. Format numbers before passing them: `{ d: num(v, 2) }`, or use `{d, number, ::.00}`.
4. **Braces and apostrophes.** A literal `{` or `}` in English text must be quoted ICU-style (`'{'`) or, better, reworded. Apostrophes in normal words ("can't") are fine.
5. **Keep the English exactly as it was**, unless the old text was a concatenation or a plural hack that rule 1 or 2 rewrites. E2E tests match English text. When you change wording, update the test.
6. **Menu paths** in prose ("File ▸ Open ▸ Open Data Pack") stay as one message. The translator translates the menu names inside it to match the translated menus (the glossary keeps them consistent).
7. **Do not translate** (leave as plain literals, add `// i18n-ignore` on the line if the lint flags them):
   - format, standard and product names (NITF, SICD, MGRS, GeoTIFF, EPSG:4326);
   - command ids, `data-id` values, CSS classes, file names and extensions, MIME types, URLs;
   - coordinate strings from the core (DD, DMS, MGRS…), units symbols inside numbers produced by `format.js`;
   - log lines that only go to `app.log(...)` and Copy Diagnostics (keep them English);
   - developer API text: `gisworkbench.api` method docs, MCP tool schemas and descriptions (they are read by AI models and scripts).
8. **AI prompts** (`ai/assistant.js` SYSTEM_PROMPT, tool descriptions) stay English. Add the UI language to the prompt instead (L-phase owner: AI group).

## Logic must not read display text (L0)
- **Dialog buttons:** `modal()` resolves with a button's `value`. Give every button `{ label: t('Jump'), value: 'jump' }` and compare with the value: `if (r !== 'jump') return;`. `buttons: ['OK', 'Cancel']` becomes `[{ label: t('OK'), value: 'ok' }, { label: t('Cancel'), value: 'cancel' }]`; the first button stays the default. Enter resolves with the first button's value; Esc and × resolve with `null`. Helpers: `confirmBox(title, message, { ok, cancel })` returns a boolean and `promptBox` a string or null; pass translated labels.
- **Toast kind:** pass the kind explicitly. A message that asks the user to do something first ("open an image first", "select a layer", "draw an AOI") is `{ kind: 'warn' }`, never `'error'`. The `STEP_FIRST` regex in `shell/toast.js` stays only as an English-only fallback.
- **Branching on errors:** replace `/^not GeoJSON/.test(e.message)` with a code: throw `gwError('not GeoJSON', null, 'E_NOT_GEOJSON')` (or set `e.code`) at the source and test `e.code === 'E_NOT_GEOJSON'`. Error codes are `E_` plus upper snake case, unique per meaning.
- **Undo labels:** `S.transact(t('Set AOI'), …)` is fine for 2.3 (the label is recorded in the language of the moment). Do not compare undo labels anywhere.
- **Sorting:** `a.label.localeCompare(b.label)` becomes `collator().compare(a.label, b.label)`.

## Numbers and dates on screen (L5)
- `fmtNum(v, d)` (shell/dom.js) is now locale-aware for display. `v.toFixed(d)` in **displayed** text becomes `num(v, d)`; `toLocaleString()` becomes `int(v)` or `num`. Values written to files, clipboard "copy value", URLs, the project file, CSV/GeoJSON and test hooks keep `toFixed` and ISO 8601.
- Displayed distances, areas, heights and speeds go through `length`, `area`, `height` and `speed` (they follow Preferences ▸ Units). Bearings and angles stay degrees.
- Displayed dates use `date`/`dateTime` (UTC by default, as imagery metadata). ISO strings stay in metadata tables where the exact value matters (label them as such).

## Drawn text, fonts and exports (L6, SDP-2.3 §4.7–4.8, S-56)
- **Canvas text** takes its font from `app/src/i18n/fonts.js`, never a literal: `canvasText(g, 11, 'label', { bold })` sets `g.font` from the theme tokens (roles `label` = `fonts.onImageLabel`, `ui`, `hud`, `mono`) and `g.direction` from the UI locale. A CJK, Arabic, Hebrew, Thai or Devanagari UI adds that script's stack (`ui-tokens.json` `fontScripts`) after the Latin fonts; Latin, Greek and Cyrillic UIs keep the Latin stack unchanged. The CSS gets the same stacks as `:root:lang(…)` rules (`build/tokens.mjs`).
- **Alignment:** text tied to a point on the image, map or chart (feature labels, measurements, scale bar, north arrow, coordinates, axis ticks) uses `pointText(g, …)` (`textAlign 'left'`): panes never mirror. Text laid out in a box (legends, captions, product titles) uses `textAlign 'start'` at `startX(x0, x1, pad)` and mirrors its swatches, so a right-to-left UI lays it out from the right (`features/aoi.js` legend, `products/template.js`).
- **PDF:** writers show text through `formats/pdf-text.js`. All text in WinAnsi → Helvetica, byte-identical to 2.2 for ASCII. Anything else → Type0 fonts subset from the `fonts-noto` pack (Noto Sans for Latin/Greek/Cyrillic, Noto Sans CJK SC/TC/JP/KR; Han by UI locale: ja → JP, ko → KR, zh-Hant → TC, else SC), with `/W` and ToUnicode. Prepare them with `await pdfFontsFor(app, strings)` (`formats/font-pack.js`) and pass them to the writer; without the pack the export still succeeds with '?' and one toast. Document information and layer names are UTF-16BE text strings. The pack is 20.8 MB (20,780,070 B: six fonts, OFL-1.1, and fontkit, MIT, with three bundle-time fixes in `build/packs.mjs`); a layered PDF of a chip with seven Japanese labels grows by about 30 KB (product PDFs draw their text into the page image and only gain UTF-16 information strings).
- **DOCX/PPTX:** `officeLang()` gives the full language tag (`en` → `en-GB`, `ja` → `ja-JP`, `zh-Hans` → `zh-CN`), the East Asian flag and font, and RTL. DOCX sets `w:lang` (val, eastAsia, bidi), `dc:language` and, for RTL, `w:bidi`; PPTX sets `lang` and `rtlMode` on every text.
- **Wave 3 (not in 2.3):** Arabic, Hebrew, Persian, Urdu, Hindi and Thai text in PDF needs a shaper (HarfBuzz, MIT, in the same pack) and bidi reordering before `fontRuns` lays a run out, plus Noto fonts for those scripts; until then those characters print as '?'.

## What the lint checks (`node build/i18n.mjs lint`)
It flags string literals passed to `toast(`, `title:`, `'aria-label':`, `placeholder:`, `label:`, `field(`, `section(`, `buttons: [`, `alertBox/confirmBox/promptBox(`, and text children of `h('tag', {…}, 'Text')`. The target is zero hits in your files outside lines marked `// i18n-ignore` (only for rule 7 cases). The lint does not see template literals (`` toast(`…${x}…`) ``) or text built elsewhere; convert those too.

## Checking your work
- `node build/i18n.mjs extract` must report no invalid ICU messages.
- `node build/i18n.mjs lint` lists what is left, per file.
- Build: `node build/build.mjs --out dist-<group> --skip-rust` (the WASM comes from `CARGO_TARGET_DIR=E:/qlab/ct23`).
- Unit tests: `npx vitest run`. E2E for your areas: `GW_DIST=dist-<group> npx playwright test <specs> --project=chrome`.
- Pseudo-locale check: start the app with the preference `locale` set to `en-XA` (Playwright: `openApp(page, 'file', { prefs: { ...LEGACY_PREFS, locale: 'en-XA' } })`) and look for English that did not change: those strings bypass `t()`.
