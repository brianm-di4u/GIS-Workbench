# GUI campaign findings register (v1.1.0, v2.0.1 and v2.0.2)

One row per finding from the GUI test and validation campaigns: v1.1.0 (GUI-001 to GUI-027, [GUI-report.md](GUI-report.md)) v2.0.1 (GUI-028 to GUI-058, [GUI2-report.md](GUI2-report.md)) and v2.0.2 (GUI-059 onwards, the visual campaign, [GUI3-report.md](GUI3-report.md)); both have sections below. The paragraph that follows describes the v1.1.0 campaign. The campaign drove the **built** Standard and Lite files through their GUI: a live, hands-on pass in a browser pane (pointer, keyboard and screenshots), and the automated sweep `tests/e2e/gui-sweep.spec.js`, which actuates every ribbon control, split caret, menu item, QAT and toolbar button, dock, context menu, layout and hot key through real input in Chrome and Edge. A finding is closed only by a passing re-test; the regression column names it.

**Severity** and **Status** follow [TE-findings.md](TE-findings.md): S1 crash/wrong result/data loss, S2 a function fails, S3 degraded or confusing, S4 cosmetic, IMP improvement. Status: Open → Fixed → Verified, or Not-a-defect.

## v2.0.2 campaign (visual: every surface, every theme, both layouts, Standard and Lite)

The 2.0.2 campaign looked at what the GUI *draws*. The visual audit `tests/tools/visual-audit.mjs` opened every surface of the Standard and Lite files (and the air-gapped file's chrome). It covered every menu and submenu, every ribbon tab, every dock, the dialogs each data state opens, the palette, pill, radial menu, tooltip, toasts, welcome card, status bar, whiteboard and video bars. It did this in all five themes of both layouts, ten combinations in all. On each surface it saved a screenshot and measured the computed colours: text against its effective background, icons and input outlines, hover and focus looks forced through CDP, adjacent regions and chart marks. The thresholds are in DN-60. A live pass in a browser pane with a GPU checked the result by eye, using the screenshots and the per-surface contact sheets `tests/tools/visual-sheet.mjs`. The token pairs of every theme are checked in `tests/unit/theme-contrast.test.js`. The regression tests are in `tests/e2e/gui3-fixes.spec.js`, titled with their id. Measured values are WCAG contrast ratios (x:1) or CIELAB ΔE76.
