# GUI campaign findings register (v1.1.0 and v2.0.1)

One row per finding from the GUI test and validation campaigns: v1.1.0 (GUI-001 to GUI-027, [GUI-report.md](GUI-report.md)) and v2.0.1 (GUI-028 onwards, [GUI2-report.md](GUI2-report.md), section below). The paragraph that follows describes the v1.1.0 campaign. The campaign drove the **built** Standard and Lite files through their GUI: a live, hands-on pass in a browser pane (pointer, keyboard and screenshots), and the automated sweep `tests/e2e/gui-sweep.spec.js`, which actuates every ribbon control, split caret, menu item, QAT and toolbar button, dock, context menu, layout and hot key through real input in Chrome and Edge. A finding is closed only by a passing re-test; the regression column names it.

**Severity** and **Status** follow [TE-findings.md](TE-findings.md): S1 crash/wrong result/data loss, S2 a function fails, S3 degraded or confusing, S4 cosmetic, IMP improvement. Status: Open → Fixed → Verified, or Not-a-defect.
