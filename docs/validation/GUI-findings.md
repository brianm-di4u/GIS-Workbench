# GUI campaign findings register (v1.1.0)

One row per finding from the v1.1.0 GUI test and validation campaign (see [GUI-report.md](GUI-report.md)). The campaign drove the **built** Standard and Lite files through their GUI: a live, hands-on pass in a browser pane (pointer, keyboard and screenshots), and the automated sweep `tests/e2e/gui-sweep.spec.js`, which actuates every ribbon control, split caret, menu item, QAT and toolbar button, dock, context menu, layout and hot key through real input in Chrome and Edge. A finding is closed only by a passing re-test; the regression column names it.

**Severity** and **Status** follow [TE-findings.md](TE-findings.md): S1 crash/wrong result/data loss, S2 a function fails, S3 degraded or confusing, S4 cosmetic, IMP improvement. Status: Open → Fixed → Verified, or Not-a-defect.
